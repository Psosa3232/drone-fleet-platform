# Initial Design Decisions

## Architecture

The project will initially use a modular monolithic architecture.

Microservices will not be used during the initial development stages.

## Database

PostgreSQL will be used as the relational database management system
for storing operational data.

## Identifiers

Database primary keys use `BIGINT GENERATED ALWAYS AS IDENTITY`.

The corresponding Java entity fields use `Long` to maintain a direct
mapping between PostgreSQL `BIGINT` and Java `Long`.

This provides a large identifier range and keeps the Java and database
types consistent.

## Java and PostgreSQL Type Mapping

Java entity field types are selected according to the corresponding
PostgreSQL column types.

The main mappings used in the project are:

| PostgreSQL | Java | Usage |
|---|---|---|
| `BIGINT` | `Long` | Primary keys and identifiers |
| `INTEGER` | `Integer` | Whole numeric values |
| `DECIMAL` | `BigDecimal` | Precise decimal values |
| `VARCHAR` | `String` | Text values |
| `BOOLEAN` | `boolean` | Boolean values |
| `TIMESTAMP` | `LocalDateTime` | Date and time values |
| `DATE` | `LocalDate` | Date values |

`BigDecimal` is used for values that require decimal precision,
such as geographical coordinates, altitude, speed, payload capacity,
and other operational measurements.

`Integer` is used for whole numeric values that do not require
decimal precision.

## Drone Models

Drone model information is separated from physical drone information
through the `drone_models` table.

This avoids duplicating technical specifications for every drone.

A drone references its model through `drone_model_id`.

## Users

Operators and maintenance technicians are represented through the
`users` table and differentiated using the `role` attribute.

## Enums

Java enums are persisted using `EnumType.STRING`.

This stores the enum name as text in PostgreSQL instead of its numeric
ordinal value.

Using string-based persistence prevents data inconsistencies if the
order of enum values changes in the future.

## Telemetry

Telemetry data is stored historically to allow future processing,
analysis, and Machine Learning.

Each telemetry record is associated with both a drone and a mission.

The telemetry dataset will later be used as a source for Data Engineering,
data analysis, and Machine Learning.

## Cache

The cache is not part of the PostgreSQL entity-relationship model.

It will be implemented later as an independent component of the
system architecture.

The cache will be used for temporary and frequently accessed data,
while PostgreSQL remains the persistent source of operational data.


## 8. Initial Persistence Layer

The initial persistence layer of the application has now been implemented using Spring Data JPA.

The following entities have repositories and integration tests:

- `User`
- `DroneModel`
- `Drone`
- `MissionZone`
- `Mission`
- `Maintenance`
- `DroneTelemetry`

Each repository extends `JpaRepository` and currently relies on the standard CRUD operations provided by Spring Data JPA.

### Entity Relationships

The main relationships implemented in the persistence layer are:

- `Drone` → `DroneModel`
- `Mission` → `Drone`
- `Mission` → `User`
- `Mission` → `MissionZone`
- `Maintenance` → `Drone`
- `Maintenance` → `User`
- `DroneTelemetry` → `Drone`
- `DroneTelemetry` → `Mission`

These relationships map the foreign keys defined in PostgreSQL to Java entity relationships using JPA annotations such as `@ManyToOne` and `@JoinColumn`.

### Integration Testing

Each repository has an integration test that verifies persistence against the PostgreSQL database.

The tests verify that:

- Entities can be persisted successfully.
- Generated identifiers are returned correctly.
- Entity relationships are persisted correctly.
- Entities can be retrieved from the database.
- Persisted values match the expected values.

### Telemetry Persistence

`DroneTelemetry` represents historical operational data generated by drones during missions.

The telemetry model currently stores:

- Position
- Altitude
- Speed
- Battery level
- Temperature
- Distance from mission start
- Timestamp

This data will later become one of the main sources for the Data Engineering layer, data analysis and Machine Learning.

## 9. Current Status

The initial relational persistence model is implemented and verified through integration tests.

The application can currently persist and retrieve the main operational entities and their relationships using Spring Data JPA and PostgreSQL.

The next development stage will focus on building application-level business logic on top of this persistence layer.
