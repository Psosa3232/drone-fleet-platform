# Initial Design Decisions

## Architecture

The project will initially use a modular monolithic architecture.

Microservices will not be used during the initial development stages.

## Database

PostgreSQL will be used as the relational database management system
for storing operational data.

## Identifiers

Database tables use numeric identifiers generated by PostgreSQL
using `BIGINT GENERATED ALWAYS AS IDENTITY`.

## Drone Models

Drone model information is separated from physical drone information
through the `drone_models` table.

This avoids duplicating technical specifications for every drone.

## Users

Operators and maintenance technicians are represented through the
`users` table and differentiated using the `role` attribute.

## Telemetry

Telemetry data is stored historically to allow future processing,
analysis, and Machine Learning.

## Cache

The cache is not part of the PostgreSQL entity-relationship model.

It will be implemented later as an independent component of the
system architecture.




## Identifiers

Database primary keys use `BIGINT GENERATED ALWAYS AS IDENTITY`.

The corresponding Java entity fields use `Long` to maintain a direct mapping between PostgreSQL `BIGINT` and Java `Long`.

This provides a large identifier range and keeps the Java and database types consistent.




## Enums

Java enums are persisted using `EnumType.STRING`.

This stores the enum name as text in PostgreSQL instead of its numeric ordinal value.

Using string-based persistence prevents data inconsistencies if the order of enum values changes in the future.
